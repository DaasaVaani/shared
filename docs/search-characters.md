# Pinned Unicode16 search-character categories

This isolated SEARCH-02/08/12/13 prerequisite supplies exact Unicode16
`General_Category` values and the already-selected ordinary letter/mark/decimal
membership test. It is **not a raw-query tokenizer**, new query-language scope,
linguistic mapping, technical-boundary decision or client capability activation.
It does not extend the personal-name folding profile or change any stored text.

## Data contract and owned settings

[Settings](../settings/search-characters.yml),
[schema](../schemas/search-characters.schema.json),
[types](../types/search-characters.ts),
[offline generator](../tools/generate-search-characters.mjs) and
[reference](../tools/search-characters-reference.mjs) define the separate
`unicode16-search-characters-v1` data component.

| Setting | Type / selected domain | Application and compatibility |
| --- | --- | --- |
| `formatVersion` | integer, exactly1 | build/explicit compatible adoption |
| `profile` | string, `unicode16-search-characters-v1` | identifies these category semantics, not a complete matching profile |
| `unicodeVersion` | string, `16.0.0` | fixed code-point assignments |
| `unicodeSourceSettings` | string, `settings/unicode.yml` | reuse authoritative original UnicodeData/license pins without copying or changing name-matching behavior |
| `ordinaryCategories` | exactly `[Lu,Ll,Lt,Lm,Lo,Mn,Mc,Me,Nd]` | approved letters/marks/decimal membership, not all numeric categories |
| `oracle.path` | `resources/unicode16/DerivedGeneralCategory.txt` | original official test oracle |
| `oracle.url` | official Unicode16 extracted-property URL | exact source provenance |
| `oracle.sha256` | lower-case64-digit SHA256 | pin every oracle byte |

Every field is required, with no coercion or default. Invalid settings/source
identities fail explicitly. These singleton settings do not permit fetched data
to broaden ordinary categories, silently upgrade Unicode or alter an active
snapshot. Consumers must explicitly bind the resource, complete matching rules,
policy identity and compatible capabilities before adoption. No consumer pin
or full matching-profile signature is supplied here.

The source and preserved Unicode License V3 remain owned by the existing
[Unicode resource guide](unicode-name-matching.md). The generator calls the
existing verified-source loader, uses only `UnicodeData.txt` for category
generation and does not call case folding, name-key generation or host Unicode
property APIs. The new independent official
`https://www.unicode.org/Public/16.0.0/ucd/extracted/DerivedGeneralCategory.txt`
oracle has SHA256
`7676ab755a41ef82108460238569e60ad65c191ddafe61b36c6765ec1353f293`.
It preserves original bytes/notices under the same Unicode license.

## Generation, provenance and validation

`npm run build` runs the generator offline. It emits
[unicode16.json](../generated/search-characters/unicode16.json) and
[manifest.json](../generated/search-characters/manifest.json):

- Strict profile/version, fixed ordinary categories and normative `Cn` default.
- Original UnicodeData/license hashes and sorted, nonoverlapping, coalesced
  inclusive `[firstCodePoint,lastCodePoint,category]` ranges.
- Manifest containing actual generated bytes/hash and original
  UnicodeData/oracle/license paths, URLs, byte lengths and hashes.

Generation validates15-field UnicodeData rows and explicit matching
`First`/`Last` range names/categories. It does not infer assignments from block
offsets or silently leave a malformed range unassigned. Reversed, duplicate,
overlapping, unmatched, malformed or unknown-category rows fail.
Adjacent equal-category ranges coalesce; explicit default `Cn` rows are not
stored. Unlisted code points are `Cn` by the UCD default, not an error fallback.
There is no timestamp, network, locale or host-version dependency.

The resource contains3,368 ranges and60,648 encoded bytes. This is deterministic
resource size, not a measured app retained/peak-memory result.
The independent derived-property file is used for exhaustive tests, not as a
substitute source for the generation algorithm.

`assertSearchCharacterData(value)` checks the strict shape, supported identity,
category domains and range invariants. Structure alone cannot authenticate
arbitrary supplied assignments or a hash-shaped claim. Establish a trusted
package/revision and verify actual manifest/resource bytes before using externally
supplied data; schema acceptance is not a linguistic or integrity certificate.

## Code-point reference API

`createSearchCharacterReference(data)` validates once, then captures independent
copies of ranges and the ordinary-category set. It returns:

- `profile`, `unicodeVersion`: the captured component identity.
- `category(codePoint)`: one of the30 exact UCD general-category values.
- `isOrdinary(codePoint)`: true only for Unicode letters (`L*`), marks (`M*`)
  or decimal digits (`Nd`).

Arguments must be integer Unicode **code points** in0..0x10FFFF. Nonintegers,
nonnumbers and out-of-domain arguments throw explicitly. This property API
deliberately includes surrogate code points, reporting `Cs` and ordinary=false;
it does not accept an ill-formed string as valid query text. A later text adapter
must validate scalar strings independently before tokenization.

Examples:

- Kannada consonants are `Lo`, virama is `Mn`, Kannada and ASCII decimal digits
  are `Nd`: all meet ordinary character membership.
- Roman numeral characters (`Nl`) and superscript numeric characters (`No`)
  are **not** decimal digits and do not meet this predicate.
- ZWJ/ZWNJ are `Cf`, not ordinary marks. Classification does not authorize their
  deletion; only the separately reviewed context-specific equivalence may do so.
- Controls (`Cc`), format characters (`Cf`), punctuation, symbols and separators
  remain distinguishable. This helper does not turn unexpected controls into
  successful ordinary boundaries or decide their user-facing error protocol.
- U+1C89/U+1C8A use their Unicode16 letter assignments regardless of the host's
  built-in Unicode version.

No normalization, case conversion, transliteration, query trimming or text
rewriting occurs. A category value cannot establish a word's language,
Source Latin eligibility or meaningful correspondence to a displayed lyric.

## Integration boundary

Ordinary membership is only one input to the full grammar.
For example, tilde is `Sm` and not ordinary, yet may belong to an approved
[technical token](technical-tokens.md). Do not split/discard all nonordinary
characters before the compatible technical profile has had its required
boundary/classification treatment. Conversely, a technical spelling's acceptance
does not make punctuation an ordinary letter.

The composition check uses actual pinned NFC and indexed verification for a
decomposed ordinary character while preserving literal source, then demonstrates
accepted technical-marker text that is not an ordinary-only run. It does not
implement or approve a scanning precedence rule.

Still required before a production tokenizer/query adapter:

- Raw ordinary-versus-technical boundary/classification semantics, including
  ambiguous punctuation and explicit unsupported-input handling.
- Scalar/query admission, controls and reviewed Kannada joiner context rules.
- Field/script/Source Latin eligibility, terminal-label exclusions, reviewed
  common/compact aliases and complete profile/policy/signature binding.
- Token-level provenance through all transformations, independent consumers,
  cooperative cancellation and actual retained/peak-memory evidence.

These are not silently resolved by this data component. Existing fixture behavior,
canonical publication, display/source text and all consumer pins remain unchanged.

## Checks and complexity

```powershell
node --test tools\search-characters.test.mjs
```

Tests compare both exact categories and ordinary eligibility with independent
official derived-property assignments for **all1,114,112 code points**.
Both official files describe the same UCD; this is an independent derivation/
parser oracle, not a claim of independent linguistic authorities.
Portable vectors cover all30 categories, Kannada marks/digits, controls,
joiners, supplementary/unassigned/private-use/surrogate points and Unicode16
additions. Tests also cover strict failures, malformed First/Last rows, complete
source/manifest identities, deterministic generation, captured independence,
no host property APIs and actual NFC/indexed/technical composition.
Finalization uses [all configured checks](data-contracts.md#validation-and-finalization).

For R ranges and N source rows, generation is O(N) work with coalescing in source
order. The captured reference uses O(R) storage and O(log R) work per lookup,
with constant lookup working state. The reference is synchronous Node tooling;
no measured query cancellation, client memory/latency or platform conformance
is established.
